Designed for inspectability
  • Equal evidence for both agentsThe judge now sees the specifications and descriptions that were available to the answering agent.
  • Invalid output fails at the boundaryMissing scores, booleans, numeric strings, NaN, infinity and values outside 0–10 raise errors before normal aggregation.
  • One authoritative calculationThe application computes the weighted overall itself. The standard fixture's correct value is 8.8.
  • Historical structure preservedOriginal code, the SQLite tables, the Next.js dashboard and project phase notes remain available.
  • Honest experiment evidenceFixture results and live model evaluations have different purposes. Human calibration and run provenance remain necessary for quality claims.

03 / Architecture decisions
The trade-offs are part of the work.
ADR / 01
Reject malformed judgements
A provider formatting failure is not an answer-quality score. Raising an explicit error keeps invalid values out of averages and anomaly baselines.
Next step: explicit failed-job records and bounded retries for unattended batches.
ADR / 02
Keep the prototype reproducible
SQLite and sequential orchestration make a single-user experiment understandable. The browser replay uses deterministic fixtures and no services.
Revisit when concurrent evaluator workers require idempotency and shared storage.
ADR / 03
Separate display from execution
The Sites page explains and replays. The original Python application owns real retrieval and optional model calls, with credentials kept server-side.
A deployed static page is not evidence that a live evaluation backend is deployed.
